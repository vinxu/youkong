# Agent 自动聊天功能

## 产品概述

### 核心理念

Agent 不是助手，是用户的**数字分身（元婴）**。它学习用户的性格、说话风格、兴趣，然后用这个"人设"去社交。

### 功能定位

极简的聊天界面：点击好友进入对话，每点一下按钮，用户的数字分身用符合用户人设的方式和朋友交流。

---

## 用户流程

### 1. 进入聊天

```
好友列表 → 点击好友 → 进入聊天页面
```

**路由**: `/chat/:conversationId`

### 2. Agent 说话

```
用户点击「让我的元婴说话」
    ↓
显示 Loading: "元婴思考中..."
    ↓
Agent 生成回复（基于人设 + 关系 + 上下文）
    ↓
消息显示在聊天界面
    ↓
通过 WebSocket 推送给对方
```

### 3. 收到对方消息

```
对方发送消息
    ↓
WebSocket 实时推送
    ↓
消息显示在聊天界面
    ↓
Agent 下次回复会考虑这条消息
```

---

## 核心系统

### 人设系统

Agent 会通过用户的行为数据和聊天记录，逐步学习用户的人设：

| 维度 | 说明 | 示例 |
|------|------|------|
| 性格 | 用户的性格特点 | 开朗外向、幽默风趣 |
| 说话风格 | 表达方式偏好 | 简洁明了、喜欢用问句 |
| 兴趣爱好 | 感兴趣的领域 | 游戏、美食、旅行 |
| 社交习惯 | 社交行为模式 | 主动约人、喜欢小聚 |
| 常用语 | 口头禅和习惯用语 | "绝了"、"救命" |
| emoji 使用 | 表情符号习惯 | 多/适度/少/不用 |
| 消息长度 | 消息长度偏好 | 短/中/长 |

**学习触发时机**:
- 每 10 次状态上报触发一次人设学习
- 每 5 条用户发送的消息触发一次学习

### 关系系统

每段好友关系都有独特的互动模式：

| 维度 | 说明 | 示例值 |
|------|------|--------|
| 亲密度 | 关系亲密程度 | 密友/普通朋友/点头之交/还不太熟 |
| 互动风格 | 互动方式 | 随意/正式/开玩笑型 |
| 常聊话题 | 经常聊的内容 | 工作、游戏、八卦 |
| 说话语气 | 和这个人说话的特点 | 轻松随意、带点调侃 |
| 开玩笑程度 | 玩笑尺度 | 高/中/低/不开玩笑 |
| 共同记忆 | 共同的经历 | 上次一起吃火锅 |

**学习触发时机**: 每 5 条消息触发一次关系学习

### 对话上下文

每对好友维护一个持久的 LLM 对话窗口：

```
┌─────────────────────────────────────────────────────────────┐
│                   LLM 对话上下文 (每对好友一个)               │
├─────────────────────────────────────────────────────────────┤
│  System: 你是帮助用户社交的AI，代替小明和小红聊天...          │
│  Assistant: 在干嘛呢？                                       │
│  User: [对方回复] 刚下班回家                                  │
│  Assistant: 今天累不累？要不周末一起吃个饭？                   │
│  User: [对方回复] 好啊，周六怎么样                            │
│  Assistant: ...                                              │
│                                                              │
│  当上下文过长时 → 总结核心信息 → 开新窗口                     │
└─────────────────────────────────────────────────────────────┘
```

**上下文管理**:
- Token 阈值: 4000
- 超过阈值时自动总结并重置
- 总结内容保留在新窗口的 System Prompt 中

## UI 设计

### 聊天页面布局

```
┌─────────────────────────────────────────┐
│  ← [头像] 好友昵称                        │  ← 顶部导航
├─────────────────────────────────────────┤
│                                          │
│     ┌──────────────┐                     │
│     │ 对方的消息    │                     │  ← 消息列表
│     └──────────────┘                     │
│                     ┌──────────────┐     │
│                     │ 我的消息      │     │
│                     └──────────────┘     │
│                                          │
├─────────────────────────────────────────┤
│  ┌─────────────────────────────────┐    │
│  │     让我的元婴说话                │    │  ← 操作按钮
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

### 消息气泡样式

| 状态 | 样式 |
|------|------|
| 自己的消息 | 右对齐，绿色背景 (`bg-emerald-500`)，白色文字 |
| 对方的消息 | 左对齐，白色背景，灰色文字，带阴影 |

### 按钮状态

| 状态 | 显示 |
|------|------|
| 默认 | "让我的元婴说话" |
| 加载中 | "元婴思考中..." + 旋转动画 |
| 禁用 | 灰色，不可点击 |

### 错误提示

错误信息显示在消息列表底部，红色文字：
- LLM 调用失败: "你的元婴罢工了"
- 网络错误: "网络错误"

## 数据流

### Agent 回复流程

```
1. 用户点击按钮
        ↓
2. 前端调用 POST /conversations/:id/agent-reply
        ↓
3. 后端获取/创建 LLM 上下文
        ↓
4. 同步对方新消息到上下文
        ↓
5. 构建 System Prompt（人设 + 关系 + 情境）
        ↓
6. 调用 LLM 生成回复
        ↓
7. 保存消息到数据库
        ↓
8. 通过 WebSocket 推送给双方
        ↓
9. 返回响应给前端
        ↓
10. 异步触发关系学习
```

### WebSocket 推送流程

```
用户 A 点击"让 Agent 说话"
        ↓
后端生成消息并保存
        ↓
┌───────────────────────────────────┐
│  WebSocket 推送给用户 A（发送者）    │
│  WebSocket 推送给用户 B（接收者）    │
└───────────────────────────────────┘
```

## 验收标准

### 功能验收

- [ ] 点击好友可进入聊天页面
- [ ] 点击「让我的元婴说话」可生成回复
- [ ] 生成的回复符合用户人设风格
- [ ] 回复考虑到与好友的关系特点
- [ ] 对方发消息能实时收到（WebSocket）
- [ ] Agent 回复后对方能实时收到
- [ ] 上下文过长时能自动总结

### 异常处理

- [ ] LLM 调用失败显示"你的元婴罢工了"
- [ ] 网络错误有友好提示
- [ ] WebSocket 断开能自动重连

### 性能要求

- [ ] Agent 回复响应时间 < 10 秒
- [ ] WebSocket 消息延迟 < 1 秒

| `13800000001` | `111111` | 测试账号1 |
| `13800000002` | `222222` | 测试账号2 |

### 测试步骤

1. **登录两个账号**
   - 浏览器 A 登录 13800000001
   - 浏览器 B 登录 13800000002

2. **建立好友关系**
   - 确保两个账号是好友

3. **测试 Agent 回复**
   - 浏览器 A 进入与 B 的聊天
   - 点击「让我的元婴说话」
   - 验证消息生成并显示

4. **测试实时推送**
   - 浏览器 A 点击「让我的元婴说话」
   - 验证浏览器 B 实时收到消息

5. **测试多轮对话**
   - 浏览器 B 手动发送消息
   - 浏览器 A 再次点击「让我的元婴说话」
   - 验证回复与上下文相关
